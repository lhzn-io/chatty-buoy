# Evaluation Framework: Next-Gen Voice & Routing

This plan outlines the benchmarking framework (a) for the **Cognitive Router** and an isolated performance bake-off (b) for **TTS Models**, specifically targeting the integration of **Mistral Voxtral (4B)** and **Salesforce VoiceAgentRAG** concepts.

---

## (a) Router Benchmarking Framework (Cognitive Router)

### 1. Objective
Evaluate the accuracy and latency of the "L0 Gatekeeper" and "L2 Dispatcher" against the **VoiceAgentRAG** "Dual-Agent Memory Router" paradigm. We want to determine if a model-based router (like a 270M-1B LLM) outperforms our current embedding-based `semantic-router`.

### 2. Candidates
*   **Baseline (Current):** `semantic-router` (Snowflake-xs) + `FunctionGemma-270m`.
*   **Candidate 1 (VoiceAgentRAG-style):** A specialized "Memory Router" (using `Gemma-3-4B` or similar) that explicitly classifies queries into `L1 (Cache/Chat)` or `L3 (Deep RAG)`.

### 3. Evaluation Dataset
A synthetic dataset of 100 queries across three categories:
*   **Ignore:** Background noise, unrelated chatter ("Pass the salt").
*   **Fast Chat (L1):** Personal questions, greetings, general knowledge ("How are you?").
*   **Deep Reasoning (L3):** Nautical RAG, complex mission planning ("Plot a course to the nearest buoy given current wind speeds").

### 4. Metrics
*   **Routing Accuracy (%):** Correct classification into L1 vs L3.
*   **Latency (ms):** Total time from raw text input to "fork" decision.
*   **VRAM Impact:** Memory overhead of the routing model vs. the embedding engine.

---

## (b) Isolated TTS Performance Bake-off (Voice Synthesis)

### 1. Objective
Determine if the **Mistral Voxtral (4B)** model can meet the <500ms TTFT (Time to First Audio) target on a Jetson Thor (simulated/target) compared to our lightweight defaults.

### 2. Candidates
*   **Current Champion:** `Chatterbox-Turbo (350M)` - Optimized for paralinguistic tags.
*   **High-Fidelity Challenger:** `Mistral Voxtral (4B)` - Recent open-weight streaming model.
*   **Fallback Reference:** `Kokoro (82M)` - Ultra-lightweight CPU/GPU fallback.

### 3. Metrics
*   **TTFT (Time to First Token/Audio):** Critical for conversational "vibe".
*   **RTF (Real-Time Factor):** Ratio of processing time to audio duration (Target: <0.5).
*   **Prosody & Tags:** Qualitative assessment of paralinguistic tag handling (`[sigh]`, `[laugh]`).
*   **Multilingual Support:** Evaluating performance on nautical terminology in non-English locales (if applicable).

## Implementation Plan

### Phase 1: Isolated Benchmarking (1-2 Days)
1.  **TTS Harness:** Create a `tests/benchmarks/tts_bakeoff.py` script that triggers all three models (via Docker) with standard nautical phrases and logs TTFT/RTF.
2.  **Router Harness:** Create a `tests/benchmarks/router_eval.py` that replays the synthetic dataset through the `semantic-router` and a "router-only" LLM call.

### Phase 2: Results Analysis (0.5 Days)
1.  Generate a side-by-side performance table.
2.  **Decision Point:** If Voxtral TTFT > 700ms, investigate quantization (GGUF/AWQ) or fallback to Chatterbox-Turbo for immediate chat, using Voxtral only for "Long-form reports" from L3.

### Phase 3: Integration (1 Day)
1.  Update `src/orchestrator/agent_orchestrator.py` to support dynamic TTS model swapping based on response length or priority.
2.  Refine the `Gatekeeper` logic based on Router Benchmark results.

---

## Verification & Testing
*   **Automated:** Compare `logs/agent/` output across different configurations.
*   **Subjective:** A "Blind Audio Test" of nautical reports generated by each TTS engine.
*   **Latency Budget:** Ensure total "Ear-to-Mouth" latency remains < 1200ms for the full cascade.
